# US 2026-09-23 data-quality incident

This is an operational diagnosis, not a change to trading rules or an acceptance of stale data.

## Observations and attribution

- The scheduled US report run [35939461805](https://github.com/EFSing/stock-data-pipeline/actions/runs/35939461805) was green while its target session was 2026-09-23 and BABA/RKLB adjusted history stopped at 2026-09-22. The US writer run [35939259087](https://github.com/EFSing/stock-data-pipeline/actions/runs/35939259087) failed; four latest rows remained pending and no formal QFQ row was updated. The prior session had the same T-1 pattern. These are separate report and Sheet writer paths.
- Both `yf.Ticker.history` and Yahoo Chart request an inclusive target date by setting the API end to the following calendar date. Yahoo Chart maps timestamps using `exchangeTimezoneName`; QFQ uses Yahoo adjusted close divided by raw close to adjust OHLC. The exact-T check then rejects a T-1 tail. A read-only probe after the incident returned 2026-09-23 QFQ from both interfaces for BABA and RKLB. This supports a time-dependent upstream publication/availability issue, but the run did not preserve raw HTTP responses, so the original upstream payload versus a transient request/parse failure cannot be proven from these observations alone. No independent licensed formal history source is approved.
- Candidate Stage A requested exactly 60 exchange sessions, beginning 2026-06-30 for US T=2026-09-23. A missing T leaves at most 59 bars even if all prior sessions were returned. The reported 59,018 Stage A rows over 1,023 seeds, 1 usable seed, and 1,022 `HISTORY_INSUFFICIENT` exclusions are consistent with that failure mode; the saved report does not expose a per-symbol bar-count/tail-date histogram, so the full population distribution is unproven. A later read-only eight-symbol batch returned 60/60 bars ending at T for BABA, RKLB, HUBB, AAPL, MSFT, AMZN, NVDA, and GOOGL. Thus the window defect is proven in code, and the incident-wide causal share remains an inference.
- Run 35939461805 also logged failed downloads for `BF A`, `BF B`, `BRK B`, and `HEI A`. The IWB CSV parser had retained spaces in share-class symbols while yfinance expects hyphens. This is a separate, smaller mapping defect; it cannot explain 1,022 history exclusions.

## Repair and acceptance boundary

- Stage A requests 70 completed sessions while keeping the existing 60-bar minimum; only exact-T tails qualify. Stale/empty batch members receive one bounded retry. A broad usable-history shortfall (`<50%` for at least 20 seeds) is reported as `PARTIAL_DATA_QUALITY`, even if one candidate is included. Genuine short histories retain `HISTORY_INSUFFICIENT`; stale tails retain `HISTORY_STALE`.
- IWB share-class spaces normalize to hyphens for the canonical candidate symbol and yfinance request. The original source symbol remains in provenance.
- The Cloud CLI still completes JSON, HTML, and notifications for a partial report. Scheduled CN/US workflows use `--require-complete`, so an operationally delivered `PARTIAL_DATA_QUALITY` report ends with a nonzero Actions conclusion; the artifact upload step uses `always()` and still runs. Existing exact-T latest/QFQ, formal writer, and strategy gates remain unchanged.
- No Sheet, Paper, production state, broker, or Final OOS write was performed. A new natural US session must confirm exact-T BABA/RKLB QFQ, verified latest, formal writer 4/4 QFQ, Stage A bar-count/tail-date coverage, included/deep-ready coverage, and JSON/HTML/email agreement. The existing CN schedule must retain its verified latest and 3/3 formal QFQ behavior.
